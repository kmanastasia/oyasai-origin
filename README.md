# OYASAI ORIGIN（仮）

**日本のお野菜を世界へ。** 畑からのお手紙。
*Japanese vegetables, to the world. A letter from the field.*

農家の話を本人の言葉のまま「畑からのお手紙」にして、お野菜を買った人が写真を読み込むとひらく。食べ方 → 想い → 農法・育て方の順に、一口ずつ読んで、聴けるサービスです。

> 登場する農家・農園・町は仮のものです（名前に「（仮）」を付けています）。価格はすべて仮で、購入や送信は行われません。読み上げは合成音声で、本人の声ではありません。

## ① 誰の・どんな課題か

おやさい旅で会ってきた農家さんたち。畑で重ねてきた判断は、書き残さないまま本人が畑を離れると消えてしまいます。

基幹的農業従事者は 103.6 万人、平均 67.7 歳（2025 年、農林水産省 令和 7 年度 食料・農業・農村白書）。

だから、本人が畑にいるうちに、本人の言葉のまま手紙にして、お野菜に添えて食べる人に届けます。

| 画面 | 誰が | すること |
|---|---|---|
| トップ `/` | だれでも | 使い方の一文（お野菜の写真を読み込むと、その農家さんからの手紙がひらきます）と、「畑からのお手紙を読む」「畑からお手紙を書く」の2つの絵の扉。巻物の絵は押すとひらき、ホバーで少し傾く。足もとに おやさい旅の Instagram・TikTok（外部リンクはこの1か所だけ）（JP／EN） |
| 農家一覧 `/choose` | 食べる人 | 10軒（仮）の農家。都道府県・品目で絞り込み。手紙がある農家は、カード右上に手紙の印（白黒＝まだ受け取っていない／色＝受け取った／ひらいた）と通数。「お野菜の写真を読み込む」「見本の写真で試す」はここにも（JP／EN） |
| 農家のページ `/farmer?id=` | 食べる人 | 農園の印（顔の絵か頭の一字）、農園・土地・品目・季節、畑からのお手紙。お野菜の写真を読み込むと手紙がひらく（QR の見本のボタンあり）（JP／EN） |
| 手紙 `/letter?no=番号` | 食べる人 | 表紙の一言（例：「まずは生で、皮ごとかじってみてください」）→「手紙をひらく」→ 01 食べ方 → 02 想い → 03 農法・育て方 の3枚。国内は「受け取る」、海外は「訪ねる」で結ぶ（JP／EN） |
| 書く `/keep` | 運営者（農家の話を聞いた人） | 送りもと・品目・季節を書き、聞き取りの音声を置き（文字起こしは準備中）、文字起こしを貼ると Claude が技・判断・土地・人に分ける。下書きでタグ・見出し・引用の範囲を直し、「手紙にする」で送る（日本語のみ） |

読む流れは 農家一覧 → 農家のページ → 手紙。手紙は、お野菜の写真を読み込んだ印（写真の読み取り、`/letter?qr=番号` の QR の URL、見本のボタンのどれか）が無いとひらきません。画面に番号（①②③④）は出しません。

## ② 3分で試せる始め方

Node.js 22.9 以上が必要です。

```bash
npm install
```

```bash
npm run dev
```

http://localhost:3000/ を開いて、次の順に押します。

**読む**

1. 「畑からのお手紙を読む」→ 農家一覧 → 「見本の写真で試す」。みなみ農園（仮）のにんじんの手紙がひらきます（API キーがあれば Claude が見本の札を本当に読み、無ければ見本としてつなぎます）
2. 「手紙をひらく」→ 01 食べ方 → 次の便箋 → 02 想い → 03 農法・育て方 → 結び
3. 右上の JP｜EN で切り替えると、英語の手紙（Translated by Claude）になり、結びが「受け取る」から「訪ねる」に変わります
4. はたけみち農園（仮）のきゅうり（No.010）も同じ流れでひらけます

**書く**

1. 「畑からお手紙を書く」→「聞き取りの見本を入れる」→「手紙の下書きにする」（音声の置き場にファイルを置けますが、文字起こしは準備中で、今は文字を貼ります）
2. 下書きで「タグや文を直す」→ タグ・見出し・引用の範囲を直せます。言葉そのものは一字も変えられず、原文にない言葉は画面でもサーバーでも受け付けません。「手紙に入れない」にした項目は、農家のページと手紙から消えます
3. 「手紙にする」→ 巻物が閉じて「畑からのお手紙が送られました」→「できあがりを見る」

**写真の読み取り**：袋や札に農園名・品目が写った写真を「お野菜の写真を読み込む」で選ぶと、Claude が文字を読んで農家一覧から1軒を選び、その手紙がひらきます（API キーが必要。写真はサーバーに残しません）。

**API キーがなくても最後まで動きます**（同梱の保存データを使います）。API キーがあっても通信せず、保存データだけで同じ流れを試すときは `npm run demo` で起動します。自分の聞き取りを Claude で分けるには、プロジェクト直下に `.env` を作って `ANTHROPIC_API_KEY=（あなたの鍵）` と書き、`npm run dev` を起動し直してください。

```bash
npm test
```

```bash
npm run verify
```

公開する前の最終確認は `npm run verify -- --final` です。【仮】の文字起こしや未確認の英訳が残っていると止まります（通常の `npm run verify` では注意だけ出ます）。

本番の文字起こしに差し替えるときは、`data/transcript.md` を書き換えて、保存データを作り直します（API キーが必要）。

```bash
npm run generate
```

2通目からの手紙は `data/letters/<番号>/` に置きます（`transcript.md`・`farm_archive.json`・`letter_assignment.json`・`translations.en.json`・`meta.json`）。`data/farmers.json` のその農家に `letter` と `letters` を書くと、一覧・農家のページ・写真の読み取りにつながります。

読み上げで目立つ読み違いがあれば、`data/speech.json` の `skip_speech_ids` に項目 id を書くと、その項目だけ読まなくなります（原文は変えません）。

英語の確認が済んだ後は作り直しません。`npm run generate` は確認済みの英訳があれば止まります。どうしても作り直すときは `npm run generate -- --keep-reviewed` で、日本語の原文が同じ確認済みの英訳を残します。

## ③ Claude の機能の使い分け

| 機能 | 何に使うか | 置き場所 |
|---|---|---|
| Skills | 聞き手の作法：`farm-archive`（聞き取りを技・判断・土地・人に分ける）、`eat-and-listen`（項目を 食べ方・想い・農法・育て方 の便箋に割り当てる）、`read-label`（お野菜の写真の文字から農家を1軒選ぶ）。アプリが実行時に読み込むので、作法の置き場所は1つだけ | `.claude/skills/` |
| Structured outputs | Claude の出力の形を JSON Schema で固定 | `schemas/` |
| フック | `git commit` の前に `npm run verify` を走らせ、失敗したら止める。農家の言葉を守る約束を、人の注意ではなく仕組みにする | `.claude/settings.json`、`.claude/hooks/` |
| サブエージェント | `label-checker`：合成音声・Translated by Claude・仮の表示と、英訳に足された理由・主語・感情を点検する。読むだけ | `.claude/agents/label-checker.md` |
| MCP | 使わない。外部につなぐ必要がないため | — |

Claude がするのは、分類・便箋の割り当て・英訳・写真の文字読みだけです。本文・方言・土地の歴史は書かせません。Structured outputs と Citations は同時に使えないので、原文との照合はコードで行います（`lib/verbatim.mjs`）。一字でも違う引用は落とし、落とした件数も画面に出します。読み上げはブラウザ標準の機能が原文をそのまま読むだけで、Claude は関わりません。

アプリの API 呼び出しはすべて `claude-opus-5-5`。effort は分類が `high`、割り当て・英訳・写真の文字読みが `medium`。`stop_reason` を確かめ、断られたときは server-side fallbacks に任せます。通信が落ちたら 1 回だけ再試行し、だめなら `data/replay/` の保存データを使います。

`npm run verify` が確かめること：quote・reason_quote の一字一句一致／理由がない判断の質問／archive_only の流出 0 件（どの項目を残すだけにしても出ないことを、全項目で試す）／英語訳の漏れ 0 件と、訳が指す原文のずれ／番号ごとの手紙（`data/letters/`）も同じ物差しで／必須の表示（農家のページと手紙の表紙の Translated by Claude、結びの「仮」の帯、≈ の出どころを含む）／送信・決済・録音・外部音声のコードがないこと（外部リンクは おやさい旅の Instagram・TikTok の2つだけ）／`private/`・`.env` が git に追跡されていないこと。

## ④ 試行錯誤の経緯

- **v1 円環暦**：語りで畑の一年を染める暦。見た目は強いが、何のために残すのかが弱かった
- **v2 コーヒー**：野菜をスペシャルティコーヒーのように見せるラベルと味のホイール。「かっこいい」が、残す目的から離れた
- **v3 残す×受け取る×買う**：農家が残し、食べる人が受け取り、買える流れに。画面と言葉が増えて重くなった
- **v4 手紙**：「未来の人への手紙」に一本化。ホイールを捨てて、手軽に選べて手軽に聴ける形にし、JP／EN と「訪ねる」を足した
- **v5 畑からのお手紙**：封をする画面と「封」の考え方をやめ、書く側は「手紙にする」の一押しに。読む側は農家一覧から、お野菜の写真を読み込んで手紙がひらく形に。便箋は 食べ方 → 想い → 農法・育て方 の順にして、まず食べ方が届くようにした

## ⑥ これから誰が使い続けるか

使い続ける人は、おやさい旅でつながった農家さんと、話を聞いて手紙にする運営者です。次の手紙は、本物の農家と書きます。

| いつ（仮） | 何を（仮） |
|---|---|
| 12/15 まで | 実在の農家さん 2 人の手紙を、同意を得て残す（仮） |
| 1/31 まで | 手紙を添えた最初の 30 箱を届ける（仮） |

ここまでの数字と日付はすべて仮です。実在の農家さんと話してから直します。
